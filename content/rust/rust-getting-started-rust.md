# Getting Started with Rust

## Getting Started with Rust

### Why It Matters

### Prerequisites

- None — this is the entry point for the Rust track.
- Basic terminal literacy (running commands, editing text files).

### Topics

- Installing Rust via rustup on Windows/macOS/Linux
- The `cargo` build system and package manager
- `cargo new`, `cargo build`, `cargo run`, `cargo check`
- Project layout: `src/main.rs`, `Cargo.toml`, `Cargo.lock`
- Release vs debug profiles (`--release`)
- `rustc` direct invocation and when you'd use it
- `rustfmt` and `clippy` for formatting and linting
- Editions (2015, 2018, 2021) and `edition = "2021"` in `Cargo.toml`

### Key Concepts

- Rust compiles to native machine code ahead of time — no runtime, no VM, no GC.
- `cargo` is the canonical build tool; you almost never invoke `rustc` by hand.
- `Cargo.toml` declares dependencies and metadata; `Cargo.lock` pins resolved versions (commit it for binaries, don't for libraries).
- The 2021 edition is the current default; prelude, closures, and module paths all behave edition-specifically.
- `cargo check` is fast (skip codegen) and is what you run in a tight loop while editing.

```bash
cargo new hello_rust --bin
cd hello_rust
cargo run
# Output: Hello, world!
```

### Common Pitfalls

- Installing Rust via `apt install rust` instead of rustup — Debian/Ubuntu's packaged Rust is typically months-to-years behind and lacks rustup component management; use rustup.
- Editing `Cargo.lock` by hand — never do this; it's regenerated by Cargo during dependency resolution.
- Running `cargo build` instead of `cargo check` while iterating — `check` is ~10x faster because it skips LLVM codegen.
- Forgetting `--release` for benchmarks — debug builds have no optimizations and run 10-50x slower than release.
- Mixing editions in a workspace — every crate in a workspace can pick its own edition, but mismatched editions can confuse macros and prelude imports; pin `edition = "2021"` everywhere.

### Real-World Applications

- Mozilla's Firefox ships the Stylo CSS engine written in Rust, replacing ~160,000 lines of C++ for parallel safety.
- Cloudflare runs Nginx-mod-replacement Rust workers on its edge via `worker` crate for low-latency request handling.
- Discord rewrote its Read States service from Go to Rust in 2020, eliminating GC pauses that caused latency spikes.
- Figma's multiplayer sync engine uses Rust for CRDT merging at native speed in the browser via WebAssembly.

### Interview Questions

- 1. What is rustup and why prefer it over a system package manager? — Per-toolchain component management (rustfmt, clippy, miri), easy version pinning, cross-compilation target install.
- 2. What's the difference between `cargo build` and `cargo check`? — `check` runs the type checker and borrow checker but skips codegen, so it's much faster for iterating.
- 3. What goes in `Cargo.toml` vs `Cargo.lock`? — `Cargo.toml` is your declared dependency spec; `Cargo.lock` records exact resolved versions and is committed for binaries.
- 4. What is a Rust edition and can a crate mix them? — Editions are opt-in language updates; a crate picks one edition, but different crates in a workspace can use different editions.
- 5. Why is `--release` important for benchmarking? — Debug builds have no optimizations and unoptimized Rust (e.g. un-inlined bounds checks) is dramatically slower than release.

### Mini Project

Build a Cargo-based Greeting CLI: A binary that takes a name as a command-line argument and prints a personalized greeting with the local time. Suggested approach:
  - Use `cargo new greeting --bin`
  - Add the `chrono` crate to `Cargo.toml`
  - Read `std::env::args()` for the name (fallback to "World")
  - Print `Hello, {name}! It is {time}.` with `println!`
  - Add a `--shout` flag using `std::env::args().any(...)`
