# Docker Volumes & Persistent Data

## Docker Volumes & Persistent Data

### Why It Matters

Without volumes, all data is lost when a container is removed. Volumes are essential for databases, file uploads, and any stateful application.

### Prerequisites

- Complete Docker lessons 01-15 first.

### Topics

- Volume types (named, anonymous, bind mounts)
- Creating and managing volumes
- Sharing data between containers
- Backup and restore strategies

### Key Concepts

- Volumes are managed by Docker and survive container removal
- Bind mounts link host directories to containers
- tmpfs mounts store data in host memory only

```bash
# Create a named volume
docker volume create mydata

# Use it in a container
docker run -v mydata:/app/data myimage

# Inspect a volume
docker volume inspect mydata

# List volumes
docker volume ls

# Remove unused volumes
docker volume prune
```
Caption: Docker volume commands

Docker volumes are the preferred mechanism for persisting data generated by and used by Docker containers. While bind mounts are dependent on the directory structure of the host machine, volumes are completely managed by Docker.

### Common Pitfalls

- Forgetting to mount volumes loses all data on container removal
- Using bind mounts in production can cause permission issues
- Not backing up volumes before operations

### Real-World Applications

- Database persistence in containerized apps
- Sharing config files between containers
- CI/CD artifact caching

### Interview Questions

- What is the difference between a volume and a bind mount?
- How do you back up a Docker volume?
- When would you use tmpfs mounts?
